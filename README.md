# Paarth Patodia, portfolio site

Live at **https://paarthpatodia.github.io/** (GitHub Pages, `main` branch of `PaarthPatodia/PaarthPatodia.github.io`, served from the repository root).

Static HTML, one stylesheet, one small script, self-hosted fonts, a handful of figures and the résumé PDF. No framework, no backend, no analytics, no third-party requests. The pages in this folder are *generated*: edit the templates one level up in `../build/` and rebuild, do not edit `site/*.html` by hand (the build overwrites them).

## Run locally

Any static server works. From this folder:

```
python3 -m http.server 8000
```

then open http://localhost:8000/. Links are relative, so `file://` also works for a quick look, but use a server to check the case-study URLs (`/work/<slug>/`).

## Build

Requirements: Python 3.9+ (standard library only).

```
python3 ../build/build.py          # from site/, or `python3 build/build.py` from the package root
```

The build walks `../build/pages/`, resolves each template's `{{include:…}}`, `{{svg:…}}` and `{{VAR}}` tags, and writes the result to the same relative path here. It refuses to write a page with an unresolved tag. Typical output:

```
wrote site/index.html (46 KB)
wrote site/work/battery-characterization-suite/index.html (60 KB)
…
```

## Page structure

```
/                                     homepage: hero, selected work, experience, about, contact
/work/battery-characterization-suite/ flagship case study (figures, validation output, educational ECM demo)
/work/infrared-target-simulator/      Leapedge prototype (conceptual diagram only)
/work/ui-element-scraper/             crawler case study with a real demonstration run
/work/automation-modules-mcode/       module-level MCode work, one engagement in detail
```

Every case study has the same sections: key result, context and role, problem, what I built, engineering decisions, demonstration, validation, limitations, links. Each page is a real directory with an `index.html`, so direct links and refreshes work on GitHub Pages without any redirect rules.

## Editing content

**Text.** Edit the template in `build/pages/…`, rebuild. Page metadata (title, description, canonical path) is set at the top of each template with `<!-- @NAME value -->` comments. The navigation and footer live in `build/partials/`; change them once.

**Content rules.** Every sentence traces to the master CV (`../content/Paarth_Master_CV_FORMATTED.tex`) or one of the two repository READMEs. Keep the qualifications that travel with the numbers: synthetic-cell provenance next to every battery figure and result, "team-reported" next to the two MCode outcome figures, "module-level" for MCode work, "under a senior engineer's guidance" for the Leapedge prototype, and "unfinished, developed with a senior engineer" for the scraper's test-execution layer. Do not list SAP as a skill.

**Adding a project.** Copy `build/pages/work/ui-element-scraper/index.html` to a new folder, set the `@` metadata at the top, add a card to `build/pages/index.html` in the Selected work section, rebuild.

**Figures.** Battery figures are SVG redrawn from the repository PNGs by `../digitize/render_svg.py` (data digitised from the PNGs; see `../digitize/*_report.md` for calibration residuals). Their colours come from the CSS classes in `site.css`, so the stylesheet owns the palette. To regenerate after re-running the toolkit: `python3 ../digitize/render_svg.py && python3 ../build/build.py`. The three conceptual diagrams (`fig-ir-chain.svg`, `fig-workflow.svg`, `fig-crawl.svg`) are hand-written SVG; edit them directly.

**Evidence blocks.** `build/svg/ev-*.html` hold the console output shown on the case-study pages, HTML-escaped. They were captured from real runs on 2026-09-22 (see the page captions). If you re-run the tools, paste the new output through `html.escape` and rebuild.

**Résumé.** Replace `assets/Paarth_Patodia_Resume.pdf`; the file name is referenced in the partials and pages. The footer and hero mention "60 KB"; update if the size changes materially.

## Publish

From this folder, on the branch you want live:

```
git add -A && git commit -m "describe the change" && git push
```

GitHub Pages rebuilds in under a minute. The redesign was prepared on the branch `redesign-2026-09`; merge it into `main` (or push it and switch the Pages source) when you are ready to go live. `.nojekyll` is present so Pages serves the folders as-is.

## Design notes

- **Type.** Bricolage Grotesque for everything in the interface (it has width and optical-size axes and drawn terminals that read as designed rather than system). Charis SIL, the open extension of Charter (the face the printed résumé is set in), only for long case-study prose. IBM Plex Mono for data, units, code and figure ticks. The root is 17px (`html { font-size: 106.25% }`) so the rem scale is exact; nothing below 14px.
- **Colour.** Cool paper, one ink, one accent: `#0B6E55`, the toolkit's own end-of-rest OCV marker green, darkened to pass AA on paper (5.6:1). The accent does three jobs: primary actions, the charge branch and OCV markers in figures, and the "what I built" outline in diagrams.
- **Motion.** One moment: the hero trace draws itself once on load when motion is allowed. Everything else is hover and disclosure. `prefers-reduced-motion` and no-JS both get the fully drawn page.
- **Figures.** Everything battery-related is toolkit output on a synthetic cell, and every caption says so.
